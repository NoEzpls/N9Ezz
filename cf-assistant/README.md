# N9Ezz CF Assistant 0.2.0 experimental

Клиентский помощник для сбора данных `/cf` с **исключительно внутриигровой валютой**.
Устанавливается только у вас: плагин сервера и установка другими игроками не нужны.
Это отдельный native addon для N9Ezz Universal Loader 0.4.1-network.1 / Minecraft 1.21.4.

Помощник записывает результаты, обучает небольшую локальную нейросеть и после
настройки создаёт ставки обычной командой `/cf create сумма`. Вы задаёте **итоговый
баланс монет**, а бот проверяет его командой `/bal` и останавливается при достижении.
Рейды и койны не учитываются. Цель — условие остановки, её достижение не гарантируется.
Нейросеть не получает доступ к генератору сервера и не знает будущий исход честного 50/50.

## Установка

1. Используйте профиль N9Ezz с
   [проверенным загрузчиком network.1](https://github.com/NoEzpls/N9Ezz/raw/8d1e463e19fbc054c618e7a55ec5a36ef6eaf672/N9Ezz-Universal-Loader-0.4.1-network.1-experimental.jar).
2. Замените старый addon 0.1.0 файлом `N9Ezz-CF-Assistant-0.2.0-experimental.jar` в
   `.minecraft/n9ezz-universal/mods/`. При другом каталоге игры используйте его
   подкаталог `n9ezz-universal/mods/`. Не оставляйте обе версии одновременно.
   Этот JAR не запускают двойным щелчком. Существующий `state.properties` сохраняется.
3. Запустите профиль, войдите на сервер и введите `/cfbot help`.

При первом игровом запуске создаётся каталог
`.minecraft/n9ezz-universal/config/cf-assistant/`:

| Файл | Назначение |
| --- | --- |
| `config.properties` | Точные шаблоны сообщений, по умолчанию `enabled=false` |
| `messages.tsv` | Кандидаты сообщений CF, подтверждения, результаты и отправленные команды |
| `messages.previous.tsv` | Предыдущий сегмент журнала, если текущий достиг 8 МиБ |
| `state.properties` | Незавершённая ставка, счётчики, веса нейросети и настройки цели |

Данные остаются локально. Журнал содержит текст сообщений и игровые имена;
никакие API нейросетей, ключи или внешние сервисы не используются.

## Первый запуск: сбор точных сообщений

Автоматические ставки **выключены по умолчанию**: в переписке были приведены
приблизительные ответы RaidMine, их нельзя считать проверенным протоколом.
Запись сообщений включена сразу. Сыграйте вручную и сохраните из `messages.tsv`
дословные ответы: создание, недостаток средств, лимит ставок, победа и поражение.
Неподтверждённые записи `OBSERVED_*` не увеличивают статистику автоматических сессий.

В `config.properties` нужны пять регулярных выражений для нормализованного полного
сообщения. Учитывайте настоящий серверный префикс и пунктуацию. Не используйте
поиск отдельного слова или общее `.*`: шаблон не должен совпадать с обычным чатом.

```properties
enabled=false
created.regex=
insufficient.regex=
limit.regex=
win.regex=
loss.regex=
```

Каждый шаблон должен начинаться с `^` и заканчиваться `$`. В файле `.properties`
обратную косую черту нужно удваивать: выражение `\d+` записывается как `\\d+`.
Например, `^\\Q[CF] точный текст ответа\\E$` — способ задать буквальный текст,
**это иллюстрация синтаксиса, а не известное сообщение RaidMine**.
Код удаляет цвета Minecraft `§`, заменяет неразрывные пробелы обычными,
сворачивает повторяющиеся горизонтальные пробелы и обрезает пробелы по краям.

Для результатов можно добавить именованные группы `(?<amount>...)` и
`(?<opponent>...)`. Эти поля необязательны. Сумма сохраняется как текст: неизвестно,
к какой базе сервер применяет указанные 15%, поэтому прибыль не вычисляется.
Если сообщение совпадает с несколькими шаблонами, оно считается неоднозначным.

После проверки всех пяти шаблонов установите `enabled=true` и выполните
`/cfbot reload`. Конфигурация с ошибкой не включает автоматическую игру.
Правильность серверных шаблонов требует проверки на реальных сообщениях;
полное совпадение текста само по себе не доказывает происхождение сообщения.

Для цели и режима нейросети также нужен **точный ответ `/bal` о вашем балансе монет**.
Команда `/cfbot balance` отправляет `/bal` и в течение 10 секунд записывает до 128
системных сообщений как `BALANCE_SAMPLE`. Там могут оказаться и посторонние
сообщения, поэтому шаблон задаётся по фактическому ответу, а не по порядку строк.
Если обновляетесь с 0.1.0, добавьте в существующий конфиг:

```properties
balance.command=bal
balance.regex=
balance.grouping=comma
balance.decimal=dot
model.scope=RaidMine-monety
```

`balance.regex` — полное выражение `^...$` с обязательной группой
`(?<amount>...)` **именно для монет**, включая реальные подписи и, если есть,
имя владельца. Не берите первый попавшийся числовой фрагмент из трёх валют.
Ответы `/bal игрок` не подходят. Поддерживаются многострочные сообщения с точным
шаблоном всего сообщения; строки не перебираются в поиске подходящего числа.

Разделители задаются явно: `balance.grouping=comma|dot|space|none`,
`balance.decimal=dot|comma|none`. Они не должны совпадать. Поддерживаются точные
значения до 10^15 с максимум двумя десятичными знаками; сокращения `1.5m` и `50k`
не считаются точным балансом. После настройки — `/cfbot reload`.

## Цель и нейросеть

Пример после проверки шаблонов CF и баланса:

```text
/cfbot goal 10000000
/cfbot start 500
/cfbot ai
/cfbot stake 1500000
/cfbot auto 500
```

Здесь цель — **10 000 000 монет на счёте**, а не прибыль 10 000 000.
`start` собирает данные ставками по 50 000. `stake` задаёт лишь потолок размера
ставки в автоматическом режиме; по умолчанию этот потолок тоже 50 000.
Включать большую сумму для обучения не нужно. Необязательный
`/cfbot losslimit 500000` ограничивает потерю относительно баланса начала сессии;
бот не создаст ставку больше оставшегося лимита. Посторонние операции со счётом
также изменяют наблюдаемый баланс и могут остановить сессию.

Встроена настоящая небольшая сеть **12 → 8 → 1**: история собственных результатов,
скрытый слой tanh, sigmoid на выходе, обучение SGD после подтверждённого исхода.
Она не использует будущий результат, неизвестного до создания ставки соперника
или скрытые данные сервера. Веса и оценки сохраняются вместе с состоянием ставки.

Первые 200 результатов — начальное обучение. Затем каждый прогноз оценивается
**до** обучения на новом результате. Для допуска к `auto` нужны минимум 100 таких
проверок и преимущество одновременно перед прогнозом 50/50 и прогнозом по общей
частоте побед, как на всей проверочной выборке, так и на последних 100 результатах.
Сравнивается ошибка Brier; это консервативный критерий, не доказательство доходности.
500 игр могут вообще не дать допуска на честном случайном сервере.

В `auto` модель выбирает ставку только при действующем допуске и оценке победы
не ниже 60%. Между 60% и 90% размер плавно растёт от 50 000 до заданного потолка,
округляется вниз шагом 50 000 и дополнительно ограничивается балансом и лимитом
потери. Максимально разрешённый потолок — 5 000 000. Это настраиваемое правило,
а не оптимальная стратегия: точная схема комиссии сервера ещё не подтверждена.

При низкой оценке или ухудшении проверки бот **останавливается**. Он не ждёт
«удачного тика»: без новых результатов история не меняется. Продолжить сбор
данных можно отдельной командой `start`. После перезапуска, смены мира, ручного
`/cf` или неоднозначного результата сбрасывается контекст последних игр;
веса сохраняются, но до повторного допуска нужно минимум 8 новых отслеживаемых
результатов и выполнение остальных критериев. Изменение `model.scope` или
шаблонов конфигурации начинает новую модель, чтобы не смешивать разные протоколы.

## Команды

| Команда | Действие |
| --- | --- |
| `/cfbot help` | Краткая справка |
| `/cfbot start 1` | Начать с одной игры для проверки настроек |
| `/cfbot start 500` | До 500 игр по 50 000 для обучения; цель и лимит также действуют |
| `/cfbot auto 500` | До 500 игр с решениями проверенной модели, обязательна цель |
| `/cfbot goal сумма` / `/cfbot goal off` | Итоговый баланс монет / отключение цели |
| `/cfbot stake сумма` | Потолок ставки auto от 50 000 до 5 000 000 |
| `/cfbot losslimit сумма` / `losslimit off` | Лимит потери от начального баланса |
| `/cfbot balance` | Получить и записать настоящий ответ `/bal` |
| `/cfbot ai` | Проверка качества модели и доступности auto |
| `/cfbot stop` | Остановить новые ставки; уже созданная остаётся на сервере |
| `/cfbot record` | То же прекращение автоматических ставок, запись продолжается |
| `/cfbot stats` | Состояние, результаты сессии и общая статистика |
| `/cfbot reload` | Перечитать конфиг, только вне активной/незавершённой сессии |
| `/cfbot reset checked` | Снять локальную блокировку после ручной проверки оставшихся ставок |

Перед `start` закройте ранее созданные ставки. Во время сессии не создавайте и не
принимайте другие ставки, в том числе через другие модули. Ответы сервера пока не
содержат известного идентификатора игры, поэтому одновременно отслеживается
**только одна** ставка, хотя сервер допускает две. Ручная команда `/cf` останавливает
помощника и запрещает приписывать последующие ответы его ставке.

Бот ждёт другого игрока для каждой созданной ставки. При включённой цели или
лимите он запрашивает свежий `/bal` перед первой ставкой и после каждого исхода,
в том числе после последней игры. Во время незавершённой ставки баланс не
проверяется, чтобы временно списанный залог не приняли за окончательную потерю.
Неизвестный или просроченный ответ `/bal` останавливает сессию, без автоматического
повтора. Баланс старше 15 секунд требует новой проверки перед ставкой.
Обычные команды отправляются не чаще раза в две секунды; ставки и автоматические
запросы баланса — только при закрытом интерфейсе.
Нет подтверждения создания за 10 секунд или результата за 180 секунд — сессия
останавливается. Нехватка средств, лимит, непонятный ответ CF, смена мира/соединения,
ошибка отправки или журнала также останавливают работу. Продолжение всегда ручное.
При сильной задержке игрового потока возможна консервативная остановка по таймауту.
Пока источник сообщений нельзя надёжно отличить, обычный чат о ставках,
переданный сервером как системное сообщение, тоже может остановить сессию.

Признак незавершённой ставки записывается **до** отправки команды. Он сохраняется
при остановке, потере связи и перезапуске. `reset checked` не посылает отмену на
сервер и не возвращает валюту: сначала проверьте/закройте оставшуюся ставку вручную.
Не удаляйте `state.properties` для обхода проверки.

500 игр — верхняя граница одной сессии, а не обещание закончить её без остановок.
Сумма ставок режима обучения — до 25 000 000 игровой валюты за сессию; в auto
она зависит от установленного потолка. Нет автозапуска при входе или
автоматического восстановления сессии. Ручной `/bal`, включая запрос чужого
баланса, прерывает ожидающую проверку; не используйте другие модули для таких запросов.

## Что показывает анализ

Счётчики включают только последовательность «своя команда → подтверждение
создания → результат» в одной отслеживаемой сессии. `/cfbot stats` показывает долю
побед и 95% интервал Wilson. При 250 победах из 500 интервал примерно 45,6–54,4%.
Этот расчёт предполагает независимые испытания с постоянной вероятностью; он не
проверяет внутренний генератор сервера и не означает вероятность следующей победы.

Имена соперников сохраняются в журнале, если настроена группа `opponent`.
Автоматический выбор соперников и клики по головам в `/cf` **не реализованы**.
Для кликов ещё неизвестны точный экран, слоты,
описания предметов и подтверждения. Не следует угадывать их и принимать чужую
ставку по случайному совпадению текста.

## Проверка и сборка

Нужны Python 3.11+ и полный JDK 21. Все зависимости берутся из проверенного
загрузчика; сборка не скачивает библиотеки и не подключается к серверу.

```bash
python3 build.py --loader /absolute/path/N9Ezz-Universal-Loader-0.4.1-network.1-experimental.jar --output-dir dist-0.2.0
```

Результаты находятся в указанном каталоге: JAR, исходники, SHA256SUMS, отчёты и логи.
Выходной каталог должен отсутствовать или быть пустым. В облачной рабочей среде:

```bash
source /workspace/toolchains/activate-temurin21.sh
python3 /workspace/N9Ezz/cf-assistant/build.py --output-dir /tmp/cf-assistant-build
```

Автоматические проверки покрывают конечный автомат, парсеры валют, цель, нейросеть,
ошибки на случайных и искусственно предсказуемых последовательностях, статистику,
сохранение состояния, интерфейс с поддельным игровым окружением и загрузку
native addon командами `--verify`/`--run`. Последние запускают API загрузчика,
**не Minecraft**. Реальная игра, выполнение игровых хуков и 500 игр на RaidMine
здесь не проверялись. Статус каждого вида проверки записан в `build-report.json`.

Подробнее о привязке к клиенту и пределах распознавания — [integration.md](docs/integration.md).
