# Архитектура N9Ezz 0.5.0

## Входные материалы

Оба предоставленных архива исходников имеют SHA-256
`6f8ba628dfe524e2b60e5724e4c3e966297e1c327daae57a96b09846b1207847`.
Это исходники выпуска 0.4.9. Приложенный TestKit содержит старый отчёт об ином
`N9Ezz-Compat` JAR, но сам JAR и исходник CompatibilityProfile отсутствуют.
Этот отчёт не используется как доказательство результатов текущего выпуска.

Доступны исходники собственного Loader, собственных контроллеров и ASM-патчей.
Полный исходник движка Pulse недоступен: `build.py` компилирует изменения и
накладывает их на закреплённый SHA-256 клиента network.1. Старые исходники в
`upstream-source/client` местами предшествуют этому двоичному клиенту. Для
спорных мест проверяется фактический байткод, а не только старый Java-текст.

## Запуск и загрузка

| Участок | Реализация | Назначение |
| --- | --- | --- |
| Установочный JAR | `dev.n9ezz.loader.launch.Main` | CLI, self-test, окно установки |
| Установка | `loader-overlay/src/main/java/dev/n9ezz/loader/launch/InstallService.java` | Отдельная версия/профиль, резервные копии, проверки конфликтов, перенос конфигурации |
| Вход игры | `dev.n9ezz.loader.launch.GameBootstrap` | Собственный runtime, загрузка модулей и преобразования классов |
| Встроенный клиент | `META-INF/n9ezz/embedded-client.json` | Ресурс, размер, SHA-256, Minecraft 1.21.11 и Java 21 |
| Инициализация Pulse | `ru.pulse.Pulse`, `pulse.TestMod` | `main` entrypoints из фактического fabric.mod.json встроенного клиента |
| Дополнения N9Ezz | `pulse.n9ezz.N9Ezz` | Реестр и события боевых модулей |

Fabric-совместимые дескрипторы и API исполняются слоем совместимости N9Ezz.
Это не установка второго официального Fabric Loader. В версии лаунчера
`inheritsFrom=1.21.11`, `mainClass=dev.n9ezz.loader.launch.GameBootstrap`,
одна собственная координата библиотеки. Файловая метка
`fabric-loader-0.19.3-1.21.4` сохранена для обновления существующих установок.

13 зависимостей сборки восстанавливаются из закреплённого оригинального Loader
и проверяются по `universal-loader/deps-lock.json`: ASM 9.9.1 (5 компонентов),
Gson 2.13.2, TOMLJ 1.1.1, ANTLR 4.11.1, Checker Qual 3.21.2,
Sponge Mixin 0.17.2+mixin.0.8.7, MixinExtras 0.5.4, Tiny Remapper 0.13.0,
Class Tweaker 0.3.0-beta.2. Компоненты ASM: core, util, tree, analysis, commons; всего зависимостей **13**. Список
в lock-файле, а не краткое перечисление, является контрактом сборки.
Fabric API и вспомогательные контрактные артефакты берутся из закреплённых
оригинальных исходников. Minecraft compile API используется только для
компиляции/фикстур и не включается в распространяемый JAR.

## Игровые события и атаки

`ClientTickEvents.START_CLIENT_TICK` начинает цикл `CombatDispatch.begin` и
очищает старый запрос. Боевые контроллеры обрабатывают клиентское событие
`ClientTickEvent`. Aura и Triggerbot штатно взаимоисключаются; наличие общих
`e.m2()` не доказывает взаимную отмену атак при штатном включении.

`AuraController.tick` выбирает цель; `TriggerV2Controller.tick` проверяет луч,
память/подтверждение цели и при необходимости прежнюю доводку. Они передают
запрос в `e.m7`. `CombatTickMixin` вызывает `CombatDispatch.afterMovement` после
обычного метода движения `class_746.method_3136`. Обработчик `e.m8` повторно
проверяет запрос и выполняет обычную атаку. `AttackCallbackMixin` учитывает
ручной удар в том же бюджете. Реальный CombatDispatch содержит защиту от
повторного callback и `finally` закрытия окна отправки, хотя старый исходник
этого класса в upstream может не содержать этих исправлений.

Монотонное время `System.nanoTime()` управляет локальным подтверждением и
планированием. Это не серверное время и не синхронизация тиков с сервером.
Отправленный запрос не подтверждает нанесённый урон. При высоком RTT и потерях
Minecraft/TCP может доставлять события с задержкой; реальные значения должны
измеряться в игровом сеансе по сценарию GAMEPLAY-TEST-RU.md.

## Пакеты и состояние сервера

`ClientConnectionMixin` публикует события пакетов; `NetworkPacketPolicy`
запрещает отмену перечисленных обязательных ответов (телепорт, скорость,
keepalive/ping/pong, обновления инвентаря и ответы на действия). Это конкретный
набор имён Minecraft 1.21.11. `CombatEntityMixin.n9ezzVelocity` сохраняет
серверную скорость. Наблюдатели в `MixinClientPlayNetworkHandler` уведомляют
Speed после обработки коррекции/скорости. Сетевые классы сохранены побайтно.
Подробности и границы автоматических проверок: NETWORK-RU.md.

## Модули, настройки и границы изменения

`u0/u1/u3/u20` — существующие классы модулей, к которым подключены собственные
AuraController, TriggerV2Controller, HitboxV3/TargetV2Runtime и SpeedV2Runtime.
`CombatSession` хранит общую цель Juggernaut. `SliderSetting`, `BooleanSetting`
и `ModeSetting` остаются в прежней системе конфигурации; ASM-патчи сохраняют
старые поля и добавленные ранее ссылки на настройки. В этом выпуске новых
настроек и миграции их значений нет.

Реестр остаётся 90 модулей: 83 Pulse и 7 N9Ezz. Классы меню,
Aura/Hitboxes/Speed и остальных функций должны совпадать с 0.4.9. Проверка
`tests/unchanged_modules050.py` сравнивает все классы клиента, разрешая изменить
только TriggerV2Controller и два класса с номером версии в сообщениях.
