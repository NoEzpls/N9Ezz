# Проверка 0.2.2 Experimental

`./build.sh` компилирует код Java 21, запускает все самостоятельные тестовые классы и только после их успешного завершения собирает дистрибутив. Авторитетный результат конкретной сборки — `build/test-results.txt`; его копия `test-results.txt` включается в ZIP исходников. Числа проверок выводит каждая тестовая программа, поэтому этот документ не фиксирует устаревающий общий счётчик.

Проверки выполняются локально, без соединения с игровым сервером и без реальных ставок. В примерах использованы искусственные ники и суммы из проверяемого формата; оригинальные пользовательские журналы в исходники не включены.

| Область | Что проверяется |
| --- | --- |
| Парсер RaidMine | Личное создание, победа, поражение, недостаток средств, просьба отменить и отсутствие ставки; `┃`, цвета, `50,000`, ранги и ники с точкой. |
| Отделение чужого текста | Упоминания `/cf`, вложенные цитаты результатов, сообщения игроков и неполные совпадения не подтверждают исход. |
| Личный баланс | Из трёх валют берутся монеты; принимается полный собственный формат, отклоняются чужой баланс и неверные разделители. |
| Машина состояний | Единственная незавершённая ставка, ожидание ACK и личного результата, проверка баланса перед следующим созданием, ограничение числа игр. |
| Восстановление | «Отмените текущую ставку» → явная проверка → «нет активной» снимает неопределённость и оставляет паузу. Локальный reset не подменяет ответ сервера. |
| Остановка | `stop`, поздние подтверждения, смена соединения и отсутствие ответов не возобновляют запуск автоматически. |
| Контроллер | Предварительный просмотр и одноразовое подтверждение; общий интервал команд, лимиты, отслеживание личного запроса `/bal`, режим без реальных ставок. |
| Денежная сверка | Победа должна дать ровно 85% ставки, поражение — списание всей ставки; следующий баланс сверяется точно, несовпадение блокирует продолжение. |
| Хранение | Перенос старого состояния, резервная копия, сохранение метаданных, повреждённые файлы и правильная запись TSV. |
| Модель 0.2.1 | Восстановленная модель сохраняет результаты и веса; повреждённые числа отвергаются, сохранение/восстановление не меняет расчёт. |

Для восстановления модели отдельно выполнено сравнение оригинального JAR 0.2.1 и восстановленного кода на одной и той же последовательности 1 200 искусственных исходов. Совпали сериализованные параметры и итоговое предсказание. Контрольная сумма этой проверки и сведения об окружении находятся в `provenance.json`. Это проверка совместимости вычислений, а не подтверждение способности предсказывать CoinFlip.

**Локальная проверка без ставок**

1. Выполните `/cfbot selftest`. Она проверяет синтетические ответы и переходы без сетевых команд.
2. При отсутствии реальной незавершённой ставки выполните `/cfbot dryrun 100`. Используется отдельный симулированный транспорт и отдельный каталог `config/cf-assistant/simulations`.
3. После симуляции проверьте `/cfbot status`: реальные счётчики, незавершённость, модель и разрешение запуска не должны измениться. Для реальной игры всё равно требуется `/cfbot start N` и новое подтверждение.

При проверке собственным Loader можно использовать его режимы `--verify` и `--run` с временными `--game-dir` и `--mods-dir`, содержащими только итоговый мод. Они проверяют нативную загрузку API. Сообщение `game runtime absent; API-only load, no game hooks installed` ожидаемо в таком режиме и не означает проверки игровых событий.

Фактически выполненные проверки нативного Loader и полный вывод приведены в [NATIVE-LOADER-VALIDATION.md](NATIVE-LOADER-VALIDATION.md).

Полноценный Minecraft, сетевое поведение RaidMine и работа в реальном AFK в этой среде не проверялись. Неизвестный ответ отмены, смена формата сообщений и задержки без идентификаторов ставок описаны в [LIMITATIONS.md](LIMITATIONS.md).
